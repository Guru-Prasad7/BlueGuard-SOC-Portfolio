AUTO-2026-001 | Analyst: Guruprasad S | Date: 14 Aug 2026

🎯 Why I Built These Scripts

Honestly? I got tired of doing repetitive tasks during my BTL1 labs. Parsing logs manually, copying IOCs one by one, and triaging alerts by hand takes forever. I figured if I'm going to be a SOC analyst, I should at least try to automate the boring stuff so I can focus on actual investigation.

These three scripts are my attempt at solving problems I've actually faced — not theoretical ones from a textbook.

🛠️ Script 1: Log Anomaly Detector

This was the first script I wrote. I was looking at auth logs during a brute-force lab and kept counting failed attempts by hand. Took me 20 minutes. The script does it in 2 seconds.

What it does: Reads /var/log/auth.log, counts failed passwords per IP, and flags anything above a threshold.

What I learned: Regex is powerful but painful. My first regex pattern caught everything including successful logins. Took 3 iterations to get it right. Also learned about defaultdict which made counting way cleaner.

# My first version had a bug — it counted ALL lines with "password"
# not just "Failed password". Fixed it after testing on real logs.

🛠️ Script 2: IOC Extractor

During phishing analysis, I kept finding IOCs in threat reports and pasting them into Notepad. Then I'd forget which IOC was which type. This script solves that by auto-categorizing them.

What it does: Takes any text (report, email, alert) and extracts IPs, domains, MD5/SHA256 hashes, and URLs using regex.

What I learned: Regex patterns for domains are tricky because you don't want to catch every word with a dot. I had to test against real malware reports to make sure it didn't flag "e.g." as a domain. Also learned about Python sets to avoid duplicates.

🛠️ Script 3: Alert Triage

This one was inspired by a BTL1 exercise where we had to prioritize 50 alerts in 30 minutes. I kept second-guessing myself — is this critical or just high? So I made a scoring system.

What it does: Scores alerts based on severity (40%), asset criticality (25%), and threat intel match (35%). Then buckets them into P1-P4.

What I learned: Scoring is subjective. My first version gave too much weight to severity and missed low-severity alerts on critical assets. Had to rebalance the weights after feedback from a practice exercise.

⚡ Challenges

  • Error Handling: My first scripts crashed if a log file didn't exist. Added try/except blocks after that lesson.
  • Performance: The log parser was slow on files >100MB. Learned about buffered reading and not loading everything into memory.
  • Real-world vs Lab: In labs, logs are clean. In reality, they're messy. I tested these on mixed formats to make sure they don't break.

💡 What I'd Add Next

I want to connect these to a real SIEM API (like Splunk's REST API) so they can pull live data instead of reading static files. Also want to add Slack/Teams notifications for P1 alerts — because no one checks email during an incident.

📝 Personal Note

These scripts aren't production-grade — I know that. But they show I can identify a problem, write code to solve it, and iterate based on testing. That's what matters for a fresher, right?
