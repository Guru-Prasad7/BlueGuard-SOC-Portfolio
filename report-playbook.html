SOC Playbook — Phishing Alert Triage

PB-PHISH-001 | Author: Guruprasad S | Version: 1.0 | Classification: INTERNAL

🎯 Purpose

This playbook provides step-by-step procedures for Security Operations Center analysts to triage, investigate, and respond to phishing-related security alerts. Following this playbook ensures consistent, thorough, and rapid response to email-based threats.

Target Audience: L1/L2 SOC Analysts
SLA: Initial triage within 15 minutes, containment within 1 hour
Priority: P2 (HIGH) — Business hours, P1 (CRITICAL) — After hours if executive targeted

📋 Step-by-Step Procedure

01

Alert Acknowledgment & Initial Assessment

Acknowledge the alert in the SIEM within 15 minutes. Gather initial context:

  • Alert source (Email Gateway, EDR, User Report)
  • Recipient email address and department
  • Sender address and subject line
  • Presence of attachments or links
02

Email Header Analysis

Extract and analyze email headers to determine true origin:

  • Check SPF, DKIM, DMARC alignment
  • Verify "Return-Path" vs "From" address
  • Inspect X-Originating-IP and Received headers
  • Check for lookalike domains and typosquats
$ dig TXT company-finance.com
$ whois 203.78.12.5
$ nslookup -type=MX company-finance.com
03

Attachment & Link Analysis

DO NOT open attachments on production systems. Use sandbox:

  • Submit attachment to Any.Run / VirusTotal / Hybrid Analysis
  • Check file hash against threat intelligence feeds
  • Analyze URLs with URLScan.io before accessing
  • Document file type, size, and creation timestamp
04

User Impact Assessment

Determine if the recipient interacted with the email:

  • Check proxy logs for URL clicks
  • Review EDR logs for file execution
  • Interview user: "Did you open the attachment?"
  • Check mailbox rules or forwarding configured
05

Containment Actions

If malicious intent confirmed, execute immediate containment:

  • Delete email from all mailboxes (eDiscovery search)
  • Block sender domain at email gateway
  • Block URLs at proxy/firewall
  • Isolate affected endpoint if file was executed
06

Documentation & Closure

Complete incident ticket with:

  • Full timeline of events
  • IOCs extracted (IPs, domains, hashes)
  • Screenshots of analysis results
  • Actions taken and lessons learned

🚨 Escalation Criteria

Escalate to L3 / Incident Response Team if:

  • Executive or C-level employee targeted (Whaling)
  • Multiple users clicked link or opened attachment
  • C2 communication detected from internal host
  • Ransomware or credential harvester identified
  • Business-critical system compromised
