SOC Dashboard — Project Analysis

DA-2026-001 | Analyst: Guruprasad S | Date: 14 Aug 2026

🎯 Why I Built This

During my BTL1 course, I kept seeing screenshots of SOC dashboards but never really understood how much work goes into making data actually readable. So I decided to build one myself — not with some fancy React framework, but with plain HTML, CSS, and Chart.js. I wanted to prove I could visualize security data without relying on tools doing all the work for me.

The goal was simple: build a dashboard that a junior analyst could look at and immediately understand what's happening in the environment.

🛠️ What I Used & Why

  • HTML/CSS: I didn't want to overcomplicate things. Pure HTML/CSS gave me full control over the dark theme and grid layout.
  • Chart.js: I tried a few libraries but Chart.js was the easiest to get good-looking charts without a steep learning curve. The doughnut chart for severity distribution was my favorite.
  • MITRE ATT&CK Mapping: I manually mapped techniques because I wanted to show I actually understand TTPs, not just copy IDs from reports.

⚡ Challenges I Faced

Responsive Design: Getting the grid to not break on mobile was annoying. I ended up using CSS Grid with media queries. Took me 3-4 tries to get the metric cards to stack properly on phone screens.

Color Choices: I initially used bright red for everything critical but it looked too aggressive. I toned it down with softer glows and shadows so the dashboard doesn't hurt your eyes during a night shift.

Real Data vs Fake Data: Since this is a portfolio piece, the data is simulated. But I made sure the numbers make sense — like having way more low alerts than critical ones, which is how real SOCs actually look.

📊 Key Features

  • Live Metrics: Top cards show total alerts, critical count, high count, and auto-resolved — the first things an analyst checks during shift handover.
  • Attack Origins Bar Chart: Shows where attacks are coming from. I used this to practice thinking like a threat intel analyst — "Why so many from Russia? Should I check GeoIP blocks?"
  • Response Time Tracking: This was me trying to think about SOC metrics. Response time matters for SLA, so I added a line chart showing how it varies by hour.
  • Alert Table: A scrollable table with severity badges and MITRE technique IDs. I color-coded statuses so you can spot open incidents fast.

💡 What I Learned

This project taught me that SOC work isn't just about tools — it's about presenting data in a way that helps humans make decisions fast. A dashboard with too much info is as bad as no dashboard.

I also learned that Chart.js config can be picky. One wrong option and your chart disappears. Debugging that made me better at reading documentation (and StackOverflow 😅).

📝 Note to Self

Future improvement: Add a real-time WebSocket connection to pull live data from a SIEM API. That would make this portfolio piece actually functional in a home lab.
